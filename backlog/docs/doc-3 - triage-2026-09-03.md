## The fresh-clone measurement

Cloned this repository to /tmp/act30probe at 516e842, `bun install
--frozen-lockfile`, then ran the suite two ways. This settles both halves of
ACT-30 and it disagrees with the card.

- `bun test src/benchmark/comparison-loader.test.ts` **alone**: 17 pass, 1
  fail, with exactly the ENOENT ACT-30 describes. Criterion #1 stands.
- `bun test` **whole**: 1015 pass, 1 fail, and the comparison-loader test is
  not the failure. An earlier test creates `.benchmark-runs`, so compare's
  ENOENT is invisible in a whole-suite run.
- The single whole-suite failure is `loadCase > resolves the declared target to
  a directory that exists`, because `cases/audit-log/case.json` declares
  `target.path` as `../../../nest/template`, a sibling repository a clone
  elsewhere does not have. That is ACT-34.
- The local checkout: 1016 pass, 0 fail before this run's fix, 1017 pass, 0
  fail after.

So ACT-30's criterion #2, "a fresh clone runs `bun test` green", was measuring
a different defect from the one its own description is about. It is rewritten
to what compare's fix can satisfy, and the outside-repo target is ACT-34.
