## The bet on ACT-122

The goal observation it should produce: an error the server forwards to a
browser no longer carries the operator's home directory, on the message shape
Node's filesystem errors actually use.

How to observe it: pass the string
`ENOENT: no such file or directory, open '/Users/<user>/code/rehearsal/x.md'`
through `redactAbsolutePaths`. Today it comes back byte-identical, verified this
run. After the fix the path is replaced and the message is otherwise intact.
AC#2 guards the other side: a relative record id containing a slash, such as
`agents/escape.md added`, must still pass through untouched, which it does
today.

Budget: no provider spend. Proposed bound, one build session.

What would falsify the bet: if widening the lookbehind also eats relative paths
or record ids, the regex is the wrong mechanism and the redactor needs to know
what a path is rather than what precedes one. Record that on the card rather
than loosening AC#2 to fit.

Sitting companion, not a merge: ACT-137 is the next High and touches a different
file, so the two can share a sitting only if the tree stays clean between them.

## Kaizen candidates, not started

The live-corpus write guard fired on this session while it was writing a triage
note whose text merely quoted a path under the agent corpus. The command was a
`backlog task edit` writing to this repository's board. So the guard currently
matches on text as well as on writes, and a session recording evidence about
corpus defects trips it. It is working as a guard and its precision costs a
retry.

over those paths was denied too. So it refuses reads, not only writes and not
only note text. That is worth a card: a guard that blocks reading the thing it
protects makes the next investigation of a corpus defect harder than it needs to
be. Not filed here, because the hook is harness configuration outside this
repository and triage does not start corpus changes. Recommended as the third
item on the authorization list below.
